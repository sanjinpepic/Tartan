## The rename: FreeSuunto → Tartan (16 Oct 2026)

The owner wants a watch-agnostic fitness coach that also works with Strava alone, so the product is now **Tartan** (the track surface, and already the app's colour). Everything user-facing changed: app name, icon (a tartan sett: crossing bands with twin overcheck threads, `web/favicon.svg`, `brandMark()` in `web/app.ts`, the Android adaptive foreground and legacy PNGs), titles, copy, the coach's identity, the MCP server name (`tartan`), the CLI (`tartan`), docs, APK files (`releases/tartan-debug-<build>.apk`).

Kept on purpose so existing installs keep working and keep their data:
- the Android `applicationId`/namespace `dev.freesuunto.app` and Java package (a new id would be a separate app without the old data; change it only with an export/import, e.g. before a store release);
- the phone's storage folder `FreeSuunto/` (`web/disk-capacitor.ts`) and every `freesuunto.*` localStorage key;
- Strava upload external ids (`freesuunto-<recording>`, `freesuunto-watch-…`), so nothing re-uploads as new;
- the PC-link header `x-freesuunto-token`;
- `$FREESUUNTO_DATA` still works next to `$TARTAN_DATA`;
- the Strava return link is now `tartan://localhost/strava`, and `freesuunto://` is still accepted (manifest and listener) for a sign-in started on an older build.
The GitHub repo is still `sanjinpepic/FreeSuunto` (renaming it is a GitHub setting; old links redirect).

## What the owner wants

The owner has a **Suunto Run 2** and uses the app privately with a few friends, with no commercial release. Their priorities, in their own words over three requests:

1. Get the watch's data off it the way the Suunto app does, on **Android and PC**. Also pull from **Strava**, because the watch already syncs there. Both paths must work.
2. Funnel all the data to LLM agents over **MCP**.
3. Map activities so each workout appears **once**, with no duplicate data points. Then:
   - beautiful dashboards, graphs and takeaways;
   - an **LLM coach** that uses their own Anthropic API key;
   - an iOS + Material You look, with one codebase restyled rather than a native rewrite.

## Done

- **Watch over BLE.** Suunto's "whiteboard" protocol, ported from SyncFix and zappctl. Code is in `src/protocol/*`, with transports for BlueZ (Linux), Web Bluetooth, and Capacitor BLE (Android).
- **Strava.** OAuth, incremental sync and rate-limit resume (`src/strava/*`).
- **Merging** (`src/merge.ts`, `src/library.ts`). Copies are matched when they overlap in time by at least 50%, are the same sport family, and their distances agree within 12%. Each field takes the best source, with provenance kept. Only one source supplies the time series. Ids stay stable via `data/activity-links.json`.
- **Analytics** (`src/analytics.ts`). TRIMP load, fitness (42-day) and fatigue (7-day), form, HR zones as % of max, easy-run efficiency, and takeaways.
- **MCP** (`src/mcp.ts`, `src/tools.ts`). 16 tools over stdio and HTTP `/mcp`.
- **Coach** (`src/coach.ts`).
  - Uses `@anthropic-ai/sdk`; the default model is `claude-opus-5-5`, with Sonnet 5.5 and Haiku 5.5 selectable.
  - Gets the read-only tools only, streams its answers, and keeps conversations under `data/coach/`.
  - The key is stored mode 600.
  - Server-side refusal fallback is on for Opus and Sonnet.
- **UI** (`web/`). One codebase for the browser and the Capacitor Android app.
  - Screens: Today, Activities with a workout sheet (pull down to close on a phone), Progress (the `#trends` view), Coach, and Settings, which holds Strava, the watch and the PC link (the old Sync tab; `#sync` still routes there). No Sync button and no freshness strip, both removed at the owner's request: `autoSync()` in `web/sync.ts` runs on open, on return to the app (visibilitychange) and half-hourly. Strava runs at most every 15 min. The paired watch runs at most every 3 h on the phone, only once it has been connected here before, and never shows a picker or the Bluetooth prompt.
  - Charts are hand-written SVG (`web/lib/charts.ts`); motion lives in `web/lib/motion.ts`.
  - The design system is documented in `DESIGN.md`, with its sidecar in `.impeccable/design.json`.
  - A design review was done and its fixes applied.

## The phone runs everything itself (done in the latest session)

The owner asked why most features needed the PC. They did because the library, Strava sync, analytics and coach used `node:fs` inside the Bun server, and the app only did watch backups. Now:

- `src/disk.ts` is a small storage interface. `src/disk-node.ts` (PC, `data/`) and `web/disk-capacitor.ts` (app-private storage, `Tartan/`) implement it. `LocalStore`, `StravaStore`, `Library`, `Analytics`, `Coach` and the cloud export take a `Disk`.
- `src/api.ts` holds all `/api` routes as a plain `Request → Response` handler. `src/server.ts` serves it over HTTP and keeps only the PC-only extras: the Strava callback redirect, the cloud export, `/api/server` and `/mcp`.
- `web/local-api.ts` (`LocalApiBackend`) runs that same handler in-process in the app. `web/state.ts` then has `app.api`, which is always there, and `app.remote`, an optional linked PC that receives watch backups.
- **Strava in the app:**
  - Connecting uses Strava's mobile flow (`/oauth/mobile/authorize`). `openStravaConsent()` in `web/sync.ts` opens it in a Chrome Custom Tab (`@capacitor/browser`: address bar, close button, "open in Chrome"). Settings also shows the link with a Copy button. Don't hand it to the Strava app: the owner found it opens the Strava app's home screen instead of the consent page.
  - Strava returns to `freesuunto://localhost/strava?code&state` (an intent filter in `AndroidManifest.xml`). `listenForStravaReturn()` catches it through `@capacitor/app` (`appUrlOpen`, or the launch URL if Android had killed the app), closes the tab and completes the sign-in.
  - Untested on a real phone: whether Strava accepts the `freesuunto://` redirect with callback domain `localhost`. Its docs show custom schemes for the mobile flow. If it refuses, register a domain and use an https App Link instead.
  - OAuth states are kept on disk, because the page reloads.
  - Strava calls go through `CapacitorHttp` (`web/native-fetch.ts`), since Strava has no CORS.
- **Coach in the app:** the Anthropic SDK runs with `dangerouslyAllowBrowser`, using the user's own key from app storage.
- **Watch pairing:** `src/transport/capacitor-ble.ts` now connects straight to a Suunto that Android already has bonded (the Suunto app's pairing; the last-used one wins), without the picker or a code. The watch card's steps on the phone say so.

## One question per screen (owner's request: no repeated information)

- **Today** (`GET /api/today`, `Analytics.today()`) answers "how am I right now?". It shows:
  - readiness in words (from form) with a reason in hours and today's advice;
  - "What do these numbers mean?", the only place fitness, fatigue and form appear as numbers;
  - the last workout's effort, ranked against your own last 3 months (`effortLabel()`), with its heart-rate mix;
  - this week day by day against the usual of the 4 weeks before;
  - "now" takeaways only.
- **Progress** (`GET /api/dashboard`) answers "how am I changing?". It shows totals for the range, month and year (not the week), weekly distance, fitness alone, consistency, intensity mix, efficiency, bests and "trend" takeaways. Takeaways carry a `horizon` that decides where each one shows.
- **Workout sheet:** "Training load" became "Effort" with a label and rank.

Don't add a card to one screen that another already shows.

## Targets and recording (latest)

**Targets** live in `goals.json`, and `Analytics.goalProgress()` works out progress against them. The API is `GET/PUT /api/goals`, and the MCP and coach tool is `get_goals`. Where they show:
- **Today:** the week card switches from "usual week" to your target. A race countdown card appears when a race is set.
- **Progress:** a dashed target line on weekly distance (`columnChart` takes a `reference`), "target met in N of 12 weeks", and a race prediction. The prediction uses Riegel from the closest best effort of the last year.
- **Settings:** the form is `form#targets`.

**Recording:**
- `src/recording.ts` holds the model, the distance filters (fixes with accuracy worse than 35 m and jumps faster than 12 m/s are dropped; pauses split segments), the time series and the TCX export.
- `web/recorder.ts` does GPS through `@capacitor-community/background-geolocation` (a foreground service) in the app and `navigator.geolocation` in a browser. Heart rate comes from any BLE device with the Heart Rate service (0x180D). It saves every 10 s and restores an unfinished run paused.
- `web/views/record.ts` is the `#record` screen, which isn't a tab; a chip in the top bar leads back to it while recording.
- Recordings are a new merge source, `phone`, ranked below strava for measurements.
- `StravaClient.upload()` posts a multipart TCX to `/uploads` and polls until done; "duplicate of activity N" counts as done.
- `STRAVA_SCOPES` now includes `activity:write`. The scope Strava actually granted is stored on the tokens (`exchangeCode(code, scope)`), and `/api/strava/status` reports `can_upload`.
- The manifest no longer caps location permissions at Android 11, because GPS needs them.

## Speed on the phone

Every read on the phone goes through Capacitor's file bridge, so the expensive parts are cached:
- `cache/hr-histograms.json`: seconds at each heart rate per activity, keyed by its stream source. Zones come from it for any max HR.
- `cache/best-efforts.json`: each Strava detail file's best efforts.
- `Library.merged()` and `Analytics.profile()` share one result for 1.5 s, because one dashboard asks for them dozens of times. `library.invalidate()` runs after a sync or backup.

The result: a reopened dashboard makes about 4 reads instead of about 800 (13 MB) for 250 workouts, as covered in `test/phone.test.ts`.

In the UI:
- Today and Progress draw their last answer at once (`lastThenFresh()` in `web/state.ts`, kept in localStorage), then the fresh one if it differs.
- `route()` stops holding the view transition for data after 120 ms.
